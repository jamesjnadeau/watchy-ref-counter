# S3-MINI-1 + RV-3028-C7 Board Implementation Plan

**Status:** the electrical design is done and green. The layout is not, and
cannot be done here. See "Where this stands" below.

**Goal:** A Watchy-compatible board in `board-files/` that replaces V2's
ESP32-PICO-D4 with an ESP32-S3-MINI-1 module and its PCF8563 with an
RV-3028-C7, drops the CP2102 and BMA423, and lands on USB-C — keeping V2's
mechanical envelope and its entire e-paper, charging and motor circuitry.

**Spec:** [`docs/superpowers/specs/2026-08-18-s3-mini-rv3028-board.md`](../specs/2026-08-18-s3-mini-rv3028-board.md)

---

## The approach changed: the board is defined in code

The original version of this plan assumed KiCad's GUI — import V2's schematic,
edit it block by block, run ERC and DRC. That is not executable in this
environment, and the reasons are worth recording because they constrain
anything done here later:

- **There is no GUI.** This runs in a headless container.
- **KiCad 8+ cannot be installed.** The agent proxy denies
  `ppa.launchpadcontent.net`, so the newest available version is Ubuntu's
  **KiCad 7.0.11**. `kicad-cli sch erc` and `pcb drc` were added in 8.0, so
  the original plan's entire verification strategy is unavailable.
- **pypi is reachable**, so code-based EDA tooling is.

So the electrical design is **atopile** source, compiled to a KiCad netlist.
This was chosen over SKiDL (netlist-level Python) and direct `.kicad_sch`
s-expression scripting because it is a real hardware description language with
a compiler, and because the resulting sources read as a description of the
board rather than as a script that edits one.

What is given up, stated plainly: there is no drawn schematic sheet. The
sources are the design.

## What is verified, and how

`board-files/checks/run.sh` compiles the sources and runs
`checks/netlist_check.py` against the netlist. Twelve check groups encode the
spec's constraints — the pin map, RTC-capable wake pins, ADC1 for the battery
tap, strapping pins, the USB-C pulldowns and D+/D- ties, the RV-3028's supply
arrangement, pull-up rails, active-low buttons, the battery divider, MCU power,
the 106 pads of the 43 parts carried over from V2, and the parts this board
deletes.

Each check was **mutation-tested**: the netlist was deliberately broken in the
way the check describes, and the check caught it. A check that cannot fail is
not a check.

ERC and DRC are **not** run, for the version reason above.

## Where this stands

**Done and green:**

1. Tooling: atopile 0.2.69 in a venv, KiCad 7.0.11 for `pcbnew` scripting.
2. V2's netlist extracted from `Watchy.kicad_pcb` — authoritative connectivity,
   not transcribed by eye from a PDF.
3. The atopile project: `parts.ato`, `mcu.ato`, `rtc.ato`, `usb.ato`,
   `watchy.ato`.
4. The check harness, mutation-tested.
5. The MCU swap, the pin map, active-low buttons, the GPIO0 pull-up.
6. USB-C with per-pin CC pulldowns, tied D+/D- halves, USBLC6-2P6 ESD;
   CP2102 and its auto-reset pair gone.
7. The RV-3028-C7 with `VDD` on `+BATT`, `VBACKUP` on `GND`, bus pull-ups on
   `+3V3`; PCF8563, crystal and CLKOUT attenuator gone.
8. BMA423 gone; battery divider at 1M/1M with a filter cap.
9. `fab/BOM.csv`: 29 line items, 54 placements. V2 placed 62.
10. V2's layout converted to KiCad 7 and switched to a 4-layer stackup, with
    every carried-over designator pinned so netlist import reuses V2's
    placement.
11. The outline dimension conflict resolved by measurement: **33.800 × 45.960
    mm** centreline. sqfmi's published 35.5 × 46.0 does not describe this
    outline. Recorded in `board-files/README.md`.

**Not done, and not doable here:**

- **Placement and routing.** Needs the KiCad GUI. `board-files/README.md`
  lists the six steps.
- **DRC.** Needs a layout and KiCad 8+.
- **ERC.** Needs KiCad 8+.
- **The RV-3028-C7 footprint.** Drawn provisionally; egress to every datasheet
  host is blocked. This is the single biggest open risk and it is blocking.
  See `board-files/UNVERIFIED.md`.
- **Fab outputs** (gerbers, drill, placement file). They follow the layout.

## Next steps, for whoever picks this up

1. Get the RV-3028-C7 datasheet, fix the footprint and its pin numbering,
   print at 1:1, check against the real part.
2. Open `board-files/elec/layout/default/watchy-ref-s3.kicad_pcb` in KiCad 8
   or 9, import `build/default.net`, place, route, DRC.
3. Export gerbers, drill files and a placement file into `board-files/fab/`.
4. Walk the physical checklist in `board-files/UNVERIFIED.md`.

## Out of scope

**Firmware.** This plan produces board files only. The firmware work — probing
I2C for the RTC instead of inferring it from the SoC, an RV-3028 driver in
`RefRtc`, the `ext1` wake mask gaining `RTC_INT`, clearing the alarm flag
before sleeping, a `board.h` revision block, and discarding the first ADC
reading — is a separate plan against the "Firmware impact" section of the spec.
It cannot be verified without a fabricated board either, but it can at least be
compiled and host-tested, which nothing in this plan can claim.

**The case.** `docs/superpowers/specs/2026-08-18-waterproof-case-design.md`
owns the enclosure. The measured outline above contradicts the dimensions that
spec assumes; that needs resolving there, not here.
